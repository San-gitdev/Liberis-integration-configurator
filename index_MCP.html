Step 03 / MCP Server Setup
Install, configure & connect
The MCP server runs on your infrastructure, makes API calls at your cost, and holds your credentials. Nothing is shared with other partners. Choose your deployment target and follow the steps.
💡 What is the MCP server? It's a small Node.js process that exposes your Liberis integration as tools that any MCP-compatible AI client (Claude Desktop, Cursor, VS Code) can call in natural language. You run it; you own it; you pay Liberis API costs directly with your own credentials.

Step 04 / Adapter Mapping
Connect your platform's APIs
The MCP server has five adapter functions that fetch data from your platform. Each one is a clearly labelled stub in the server file. Replace them one by one — you don't need to replace all of them before testing.
💡 How adapters work: When Claude calls a Liberis tool (e.g. get_offers), the MCP server calls your platform's API to fetch the merchant data it needs, then passes it to Liberis. The adapter functions are the bridge between your data and Liberis's expected format.
Adapter functionWhat it fetchesUsed by toolsStatus
getPlatformMerchant Merchant legal name, entity type, address, join date register_merchant, get_offers, run_onboarding_flow MOCK
getPlatformRevenue 12 months of aggregated revenue (date, amount, count) submit_revenue, get_offers, run_onboarding_flow MOCK
checkPlatformEligibility Your platform's eligibility gate before Liberis underwriting register_merchant, run_onboarding_flow MOCK
storeLiberisId Write liberis_id to your database after first offer get_offers, reprice_offer MOCK
getLiberisId Read stored liberis_id for renewal detection get_offers, reprice_offer MOCK
Replacing an adapter — example
// BEFORE (mock stub in liberis_mcp_server.ts): async function getPlatformMerchant(merchantId: string) { console.error(`[ADAPTER] getPlatformMerchant — replace with real call`); return { partnerId: merchantId, entityType: 'SoleTrader', ... }; } // AFTER (your real implementation): async function getPlatformMerchant(merchantId: string) { const res = await fetch( `https://api.yourplatform.com/v2/merchants/${merchantId}`, { headers: { Authorization: `Bearer ${process.env.PLATFORM_API_KEY}` } } ); const m = await res.json(); return { partnerId: m.id, entityType: mapEntityType(m.businessType), // map to Liberis taxonomy clientStartDate: m.joinedAt.slice(0, 10), legalName: m.registeredName, address: { line1: m.address.street, town_city: m.address.city, postcode: m.address.postcode, country: 'UK' }, email: m.contactEmail, phone: m.contactPhone, }; }
Entity type mapping — Liberis taxonomy
// Map your platform's entity types to Liberis values: function mapEntityType(yourType: string): string { const map: Record<string, string> = { 'sole_trader': 'SoleTrader', 'limited_company': 'LimitedCompany', 'llc': 'LLC', 'partnership': 'Partnership', }; return map[yourType] ?? 'SoleTrader'; }

Step 05 / Day 1–20 Runbook
Your integration playbook
A realistic timeline from first install to production-ready. The MCP server unlocks sandbox testing on Day 1 — production readiness takes longer because of regulatory and security gates, not technical complexity.
Day 1
Install & first sandbox call
1.1
Download the bundle — clone the repo or download the zip. You need liberis_mcp_server.ts and the generated .env file from Step 3. DEVELOPER
1.2
Get sandbox credentials — contact your Liberis partner manager. They issue a client_id and client_secret scoped to the sandbox environment. LIBERIS
1.3
Fill in .env — paste your sandbox client_id and client_secret into the generated .env file. Do not commit this file to version control. DEVELOPER
1.4
Install and connect — follow the install steps in Step 3 for your chosen client (Claude Desktop / Cursor / Cloud). DEVELOPER
1.5
First test call — ask Claude: "Run the onboarding flow for merchant MERCH_001". The MCP server authenticates, registers a test merchant, submits mock revenue, checks eligibility, and returns offers. The ADAPTER functions return mock data — this is expected. MCP SERVER
Days 2–5
Replace adapters with real platform calls
2.1
Start with getPlatformMerchant — the most impactful adapter. Replace the mock with a real call to your merchant API. Pay attention to the entity type mapping (Liberis taxonomy vs your taxonomy). DEVELOPER
2.2
Replace getPlatformRevenue — exclude the current partial month, use negative values for returns. Test with a merchant that has 12 months of actual data. DEVELOPER
2.3
Implement checkPlatformEligibility — add your minimum months on platform check and minimum revenue threshold from Step 2 config. DEVELOPER
2.4
Wire up storeLiberisId and getLiberisId — these need a database write and read. Add a liberis_id column to your merchants table. Without this, renewals will not work. DEVELOPER
2.5
End-to-end sandbox test — ask Claude: "Register merchant [real_merchant_id] and show me what they qualify for". This now runs with your real platform data against the Liberis sandbox. MCP SERVER
Days 6–10
Validate sandbox behaviour & type shapes
3.1
Compare response shapes — check that the Liberis sandbox responses match the TypeScript types in the server file. The sandbox sometimes returns fields not in the documentation. Update types where needed. DEVELOPER
3.2
Test offer acceptance — ask Claude: "Accept the lowest offer for merchant [id]". Check that application_id is returned and deal events arrive at your webhook endpoint. DEVELOPER
3.3
Test renewal flow — simulate a returning merchant by manually setting a liberis_id in your database, then run get_offers again. Confirm the renewal payload is sent (contains liberis_id in the request). DEVELOPER
3.4
Test edge cases — ineligible merchant (expect null from check_eligibility), expired offer acceptance (expect HTTP 409), revenue validation failure. DEVELOPER
Days 11–15
Security hardening before production
4.1
Add HMAC webhook verification — the handle_webhook stub currently has no signature check. Add HMAC-SHA256 verification using your Liberis webhook secret before processing any event. DEVELOPER
4.2
Move credentials to a secrets manager — do not use .env files in production. Use AWS Secrets Manager, HashiCorp Vault, Railway Secrets, or equivalent. Rotate client_id/client_secret to production values. DEVELOPER
4.3
Confirm data residency routing — UK/EU merchants must use platform.eu.liberis.com. US merchants must use platform.us.liberis.com. The base URL must be determined by merchant domicile, not partner location. DEVELOPER
4.4
Add structured logging — log every Liberis API call (timestamp, operation, merchant_id hashed, response status, latency). Do NOT log request bodies — they contain PII. DEVELOPER
Days 16–20
Liberis partner approval & production launch
5.1
Submit for Liberis partner review — share your integration approach, UI copy (for mandated terminology check), and webhook endpoint with your Liberis partner manager. LIBERIS
5.2
UI copy compliance check — Liberis has mandated terminology for how financing is described to merchants. Your partner manager will review and approve your copy. LIBERIS
5.3
Switch to production credentials — update LIBERIS_CLIENT_ID, LIBERIS_CLIENT_SECRET, LIBERIS_BASE_URL, and LIBERIS_ENV=production in your secrets manager. Restart the MCP server. DEVELOPER
5.4
Soft launch with first merchant — run "Register [real_merchant_id] and show me their live offers" in Claude. Confirm a real offer is returned with real underwriting. MCP SERVER
5.5
Monitor first week — watch webhook delivery, balance API response times, and revenue claim validation rates. Set up alerts for validation failures > 5%. DEVELOPER
